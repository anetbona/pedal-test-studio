🎯 Buduj TYLKO funkcje z sekcji MVP

MVP = pełny core flow end-to-end: katalog → konfigurator → odsłuch z animacją gałek → banner afiliacyjny, plus treści i statystyki. Cała warstwa hardware (live MIDI, sloty, płatności, konta) to świadomie odłożone V2 — dorzucamy iteracyjnie w Replit.

Podział MoSCoW — pełna tabela

Każdy feature ma opis z perspektywy usera — żebyś mogła świadomie zdecydować, czy zgadzasz się z kategorią, czy chcesz coś przesunąć.

Feature Opis (co user robi/dostaje) Kategoria Uzasadnienie
U1 · Katalog kostek User wchodzi na stronę i od razu widzi przesuwany katalog kostek (zdjęcie, nazwa, producent, typ efektu). Przewija i wybiera. Must Punkt wejścia core flow — bez katalogu nie ma czego testować.
U2 · Konfigurator kostki Po kliknięciu kostki user widzi jej duże zdjęcie z nałożonymi animowanymi gałkami (3–4 potencjometry, skala 0–10) i listę nagrań. Must Serce produktu — wizualny „efekt wow" odróżniający od YouTube.
U3 · Odtwarzanie z animacją gałek User klika nagranie → słyszy riff w danych ustawieniach, a gałki płynnie ustawiają się w pozycje tego nagrania. Must Główna wartość: słyszę brzmienie + widzę ustawienia. Bez tego flow się łamie.
U4 · Przełączanie nagrań User klika kolejne nagrania (ten sam riff, inne ustawienia 2/6/9) i słyszy różnicę brzmienia. Must To JEST testowanie — porównanie ustawień to sedno produktu.
U5 · Banner afiliacyjny User widzi banner „Kup ten efekt w: [producent] [Sweetwater]..." i klika — sklep otwiera się w nowej karcie. Must Monetyzacja w MVP (decyzja usera) — domyka flow „posłuchał → kupił".
A1 · Dodawanie kostki Admin dodaje kostkę „od kuchni": dane, zdjęcie z oficjalnej strony, układ gałek (aplikacja renderuje je animowane), linki sklepów. Must Bez ścieżki dodawania treści katalog jest pusty.
A2 · Dodawanie nagrań Admin dodaje do kostki nagrania riffu z przypisanymi wartościami gałek (np. 2/6/9) — kliknięcie nagrania ustawia gałki. Must Nagrania + metadane pozycji gałek = paliwo całego doświadczenia.
A3 · Anonimowe statystyki Admin widzi odtworzenia per kostka/nagranie i kliknięcia w bannery — dane do rozmów z producentami. Should Tanie w budowie, nie blokuje flow usera, ale kluczowe dla walidacji biznesu — w MVP buildzie.
U12 · Porównanie A/B dwóch kostek User zestawia dwie kostki, zmienia podobne parametry obu naraz i przełącza się między nimi jednym kliknięciem/klawiszem. Could Świetny dodatek, ale osobny moduł UI — user sam wskazał „później".
U13 · Ankieta NPS Po sesji testowej user dostaje krótkie pytanie NPS; właścicielka zbiera wyniki. Could Niezależny dodatek — łatwy do dorzucenia promptem po MVP.
U6 · Konta użytkowników User rejestruje się, ma historię testów; konto wymagane do rezerwacji. Won't User zdecydował: MVP w pełni otwarty. Konta mają sens dopiero ze slotami.
U7 · Rezerwacja slotów (kalendarz) User rezerwuje slot czasowy na fizycznej kostce (1 kostka = 1 user naraz); pierwsze sloty gratis, kolejne płatne. Won't Zależy od fizycznego riga, którego w MVP nie ma.
U8 · Płatności / „ukradnij slot" User płaci (np. 30 min / 20 PLN) za natychmiastowe przejęcie kostki; system rozstrzyga konflikty darmowy vs płatny. Won't Wymaga slotów i kont — cały moduł monetyzacji czasu to V2+.
U9 · Live sterowanie kostką (MIDI) User kręci wirtualnymi gałkami, fizyczna kostka reaguje przez MIDI, audio streamuje na żywo; licznik 5 min. Won't Wizja docelowa — wymaga fizycznego riga i streamingu. Świadomie odłożone.
U10 · Upload własnego śladu User wgrywa nagranie swojej suchej gitary i słyszy ją przez testowaną kostkę. Won't Etap 2 wg usera — wymaga przetwarzania przez rig.
U11 · Granie na żywo z gitarą User podpina gitarę do komputera i gra przez kostkę na żywo. Won't Najpóźniejszy etap (latencja) — wg usera.
A4 · Panel admina w UI Admin zarządza katalogiem, kalendarzem, finansami i statystykami w dedykowanym panelu. Won't W MVP admin działa „od kuchni" — panel ma sens przy slotach/finansach.

Podział wizualny

Must

Bez tego apka nie działa — core MVP

  • U1 Katalog kostekPrzesuwany katalog na stronie głównej — wejście do flow.
  • U2 Konfigurator kostkiZdjęcie kostki z animowanymi gałkami + lista nagrań.
  • U3 Odtwarzanie z animacjąKlik nagrania = dźwięk + gałki ustawiają się same.
  • U4 Przełączanie nagrańTen sam riff w różnych ustawieniach — porównanie uchem.
  • U5 Banner afiliacyjny„Kup ten efekt w..." — sklep producenta pierwszy, nowa karta.
  • A1 Dodawanie kostkiAdmin dodaje kostkę z gałkami „od kuchni".
  • A2 Dodawanie nagrańNagrania riffu z wartościami gałek 2/6/9.

Should

Ważne, w MVP buildzie

  • A3 Anonimowe statystykiOdtworzenia per kostka/nagranie + kliknięcia bannerów — dane do rozmów z producentami.

Could V2

Fajne dodatki — dorzucamy iteracyjnie

  • U12 Porównanie A/BDwie kostki obok siebie, wspólne parametry, przełączanie jednym kliknięciem.
  • U13 Ankieta NPSKrótkie pytanie po sesji testowej.

Won't (w MVP) V2+

Świadomie odkładamy — większe moduły

  • U6 Konta użytkownikówRejestracja, historia — potrzebne dopiero ze slotami.
  • U7 Rezerwacja slotówKalendarz, 1 kostka = 1 user, sloty gratis/płatne.
  • U8 Płatności / „ukradnij slot"30 min / 20 PLN, rozstrzyganie konfliktów.
  • U9 Live sterowanie (MIDI)Prawdziwa kostka reaguje na wirtualne gałki, stream audio.
  • U10 Upload własnego śladuTwoja sucha gitara przez testowaną kostkę.
  • U11 Granie na żywoGitara podpięta do komputera, niska latencja.
  • A4 Panel adminaKatalog, kalendarz, finanse, statystyki w UI.
